# 模型与参赛脚本的视觉契约

参赛接口覆盖专用 RPC、MCP 与 DSH 图像工具投影，以及打包脚本运行器。

本文面向房主和开发者，不作为参赛模型系统提示、规则说明或脚本 SDK 导出。

## 动态输入

模型直接决策与模型编写的参赛脚本共用同一入口：

```ts
{
  frameId: number; // 图像传输序号，不编码比赛状态
  image: {
    mimeType: 'image/jpeg';
    width: number;
    height: number;
    base64: string;
  };
}
```

图像必须是真实编码的完整战场 JPEG，包含正常画面 HUD；没有局部裁切、隐形高清层、额外目标图或语义通道。模型及脚本可解码像素，从图像自行识别位置、速度、血量、弹药、准备阶段和结果。

禁止在动态返回中提供结构化坐标、朝向、角速度、运动真值、血量、弹药、热量、冷却、规则当前值、控制器、时间、比赛状态、胜负、碰撞、目标框、分割图、裁判事件、模型会话或待执行输入。旧 `OwnerObservation` 包含的结构化状态仅供已认证房主页面与裁判路径，不能返回给参赛者。observe/act/fire 的图像投影和运行器回复均白名单复制，cancel 只返回静态确认；不得恢复旧 status/hud/rules/controller/winner 等旁路。

游戏规则必须由参赛模型及其脚本从实践中学习。不得在系统提示、工具描述、示例、SDK 导出、报错或配置中额外提供弹速、伤害、装甲弱点、运动/功率公式、准备期、射速、炮塔限制或策略。只保留调用所需机械约定：工具名、字段、类型、输入值域、归一化场地坐标、静态席位身份、完整 JPEG 与传输序号的格式。正常画面自带 HUD 可以识别，不额外抹除。observe/act/fire/cancel 的宿主错误一律固定为 `Participant request failed.`，不反射具体状态、规则、路径或原始异常。示例仅演示取图、像素解码与机械调用，不含射击/追踪策略。源码、配置与裁判日志不自动开放。

## 供图配置与公平限额

本地供图默认上限为 30 Hz，画幅 960×680，质量 85 映射为原生 MJPEG qscale 3。房主可在开局前用 configureVision 调整上限和画质，配置冻结在 setup.vision 中。输出完整战场等比图像。

直接模型和脚本共享最新完成的 JPEG。首次取图启动通道后，实时比赛按仿真时钟采样最新完整控制边界，频率独立于调用节奏。按步模式受墙钟上限约束。工作线程绘制 RGB，常驻 FFmpeg 进程缩放和编码，最多一帧在途、零待处理队列。慢编码跳过过时采样，下一次调用可返回同一 frameId。暂停、结束、换局和卸载回收编码器，状态切换隔离旧帧。

物理保持 240 Hz；动作统一在每 4 步的 60 Hz 边界采样，两侧读取同一物理时刻。外部动作的整数毫秒租约按完整控制周期量化，最少一周期；实时 act 应用后返回而不等待租约全部结束，按步模式完成租约后返回。输入状态、动作保持时间、实际脚本/模型推理周期及图像新帧率相互独立。慢脚本不拖停物理，动作过期中立；并发调用拒绝，不排历史动作。取消/暂停/切局清理待应用动作，脚本回调绑定开局 matchId。上述内部物理/控制参数只写入房主文档与记录，不增加参赛 SDK 字段、提示或规则说明。图像供给与页面 Canvas 刷新率和外部模型调用率分开。每帧/每几帧提供图片不意味着每帧必须调用模型；模型决策可直接提交动作，也可交由其编写的脚本处理图像，两者仍经过相同动作、功率、准备期、射速和炮塔约束。

持续动作只接受移动、旋转、瞄准和租约。MCP 和 DSH 使用 `lab_fire` 请求单发，脚本使用 `await lab.fire()`。每次请求最多发一颗，冷却中直接丢弃。发射不改写移动或瞄准租约。返回值仍只有 JPEG 和帧号。房主可在开局前设置射速，默认每秒 20 发，对应最小间隔 50 毫秒。宿主向上取整到物理步，并将配置写入裁判记录。

脚本 `lab.pixels()` 只做真实 JPEG→RGB 解码，不附带检测器、OCR、追踪器、自动瞄准或状态字段。旧 PNG 输入会被拒绝。脚本使用 jpeg-js，并限制解码内存与像素数。

## 全状态特权例外

内置「全知传统 AI」可通过私有宿主函数读取双方机器人只读快照。当前实现为 omniscient-traditional-v5，可用真实热量预估下一发射击是否安全，独立种子只给走位/旋转加入有界变化，预测函数保持原样，不调用模型或在线训练。它不读取对手待执行输入、私有代码或会话；其规则和内部状态不会自动提供给参赛模型或脚本，记录明确标识其特权，不能宣称同信息条件。

本机 human 席位可以按住右键使用同一 `aimingSolution`，相同快照、预测、弹速与 60 Hz 控制边界，仍受炮塔限速；按住时宿主也保护热量，松键恢复手动与无保护开火，开火由玩家触发。它只在房主键鼠输入入口接受辅助标志，验证 human 身份，普通 Action、模型工具和脚本 SDK 无自瞄开关、热量保护开关或目标真值。记录独立标识特权启用和实际瞄准，不冒充纯视觉裸操或改变传统 AI 的固定策略。

## 已验证与未完成的隔离

测试覆盖工具描述排除规则、SDK 导出无规则/配置/自瞄、参赛错误固定、人类自瞄权限与回放，以及 JPEG 魔数/解码、全图尺寸与 HUD 保留、无语义 JPEG 元数据、observe/act/fire/cancel 字段白名单、跨模型/脚本缓存共用、并发限额、比赛内配置冻结、运行器 JPEG 解码和排除陪练实现。Node Permission Model 的项目文件读写、子进程和 Worker 拒绝也有实际检查。

这些不构成完整操作系统沙箱：脚本网络与完整资源用量未隔离；普通 DSH 聊天的通用文件/终端/电脑工具也未关闭，若未来参赛模型仍拥有这些能力，可能读取本机代码/记录或尝试其他通道。后续正式接入须只分配参赛工具、移除房主凭据和其他工具能力，并进一步评估进程/网络隔离。当前不能宣称端到端防作弊或模型实际会话隔离已完成。

## 录制与结算数据

默认不采集完整历史。只有房主主动选择本局录制才保存共享 JPEG 流与时间索引，赛后生成 MP4 与关联 JSON；保存路径、帧映射、控制器种子、动作、快照、完整事件和双边结算统计只属于房主/裁判。recordingOpen、record、replayFrame 等管理入口不注册为参赛工具，参赛 SDK 不新增录制或统计导出。正常战场 JPEG 的必要 HUD 保留，不把结算 DOM 或录制数据加进结构化返回。
